# TIPS.md

Compiler quirks and matching tricks that keep costing time. Each entry is "what you see in the diff, what to try, where it was seen". Confidence: **HIGH** = seen in several places or fixed by the compiler's rules, **MED** = seen once with a stated reason, **LOW** = folklore. Add what you learn (short, with a source file), and keep entries factual.

The same assembly can come from very different C++ (`add r3,r3,r4` could be `x + y` or a pointer-offset helper). Matching bytes is not enough: pick the version that fits how the game is structured, name things by evidence, and tag guesses with `// HYPOTHESIS:` and match-only hacks with `// MATCH-ONLY:`.

## Source review before accepting a match

Adapted from [decomp-triage](https://github.com/KakarottoCake/decomp-triage/tree/ccdf17ba8ad68f4615fe0aef3db523dcd7f906bf), reviewed against Brawl main `8310c2ff`. These checks are advisory evidence prompts, not automatic verdicts.

- **Raw offsets and flattened copies:** verify the receiver, member extent, access width and callers. Use existing typed members when they describe the observed accesses; keep unknown names `unkN`. Casting an entire structure to a float array can cross non-float fields and hides its layout. `hkMotion::getMotionStateAndVelocities` is a review example. **HIGH**
- **Padding and helpers:** distinguish an unused local added to alter the frame from real structure padding. A one-use helper can be a useful abstraction, and an unreferenced symbol can have been dead-stripped. Check source provenance, maps and linked output before deleting it. Neither a helper count nor a regex establishes authenticity. **HIGH**
- **Anonymous data normalization can hide a wrong dynamic cast:** follow the RTTI record's first relocation to the actual class-name string, then verify its base list and member layout. A nearby string is not the type descriptor, and an exact scorer result can survive the wrong cast when anonymous labels are normalized. Seen: `ft_dedede_status_uniq_process_special_super_jump.cpp` and its Jump unit (controller, gravity and stop energies). **HIGH**
- **Bytes, relocations and availability:** compare relocation targets as well as instruction bytes. Identical relocatable call instructions can name different callees. Missing objects are unavailable evidence, not exact functions or cheap dependency leaves. Keep drafted, object-exact and source-linked progress separate; retain the full 127-output gate and original module/address/size regression comparison. **HIGH**
- **Variant generators require semantic review:** the reviewed generator proposed `x != 0` -> `x == TRUE` for an integer (different at `x = 2`), and reassociated `float a + b + c` despite its integer-only description. Check boolean domains, evaluation order, overflow, aliasing and floating-point rounding before trying a rewrite; a higher percentage does not validate it. **HIGH** (reproduced on the cited revision)

## 0. Check the build flags before the C++
- If a whole class of units is off the same way (scheduling, stack frames, extra weak symbols), the compiler flags are the suspect, not the code. Fighters and `sora_enemy` build with `-O2,s`; Havok uses `-RTTI off -use_lmw_stmw on`, some units `-Cpp_exceptions on` or `-inline noauto`; some units `-RTTI off`. Flags are set per unit in `configure.py` (`extra_cflags`). Seen: `cflags_*` in `configure.py`, commit a5cc934 (ft_purin). **HIGH**
- `-Cpp_exceptions on` makes `.extab/.extabindex` appear; `-RTTI off` removes `__RTTI__` weak data and the dynamic_cast machinery; `-use_lmw_stmw on` gives `lmw/stmw` prologues.
- Optimizer pragmas that exist in MWCC but are not yet used in Brawl code (Petari uses them often): `opt_propagation off`, `opt_common_subs off`, `opt_loop_invariants off`, `opt_lifetimes off`, `global_optimizer off`. Worth trying when one load is extra or missing or a value is spilled. Always bracket with `#pragma push` / `#pragma pop`. **MED** (names real, per-site effect untested here)

## 1. Pragmas
- **RVL SDK units sometimes need a different flag set, not different code:** `EXIBios.c` only lined up after `extra_cflags=["-schedule off"]` (11 of 19 functions went exact; loads/stores were interleaved, the register picks were right). `dvd_broadway.c` needs `-lang c99` with `#define bool _Bool` before the includes (a real boolean: casts such as `(volatile bool)x` then give the `neg/or/srwi` normalisation) and `#undef NULL` / `#define NULL 0` (the `(void *)0` flavour compares with `li r0,0; cmplw` instead of `cmpwi r3,0`). Try these three before touching the logic. Seen: `src/RVL_SDK/exi/EXIBios.c`, `src/RVL_SDK/dvd/dvd_broadway.c`. **HIGH**
- **A static whose initialised data lands in `.sdata2` instead of `.sdata`:** the initialiser of a local aggregate (`GXColor c = {..}`) is read-only data. Declare `static GXColor cInit = {..};` and copy it (`GXColor c = cInit;`) to get the writable `.sdata` source with the same byte-wise copy. Seen: `src/RVL_SDK/dvd/dvd_check.c`. **MED**
- **A function at the front of a unit whose callees were not inlined, while the same callees are inlined everywhere else in the unit, is a different source file:** look for statics that sit before the unit's other data in every section (`.sdata`, `.sbss`, `.bss`, `.rodata`) and split it off in `splits.txt`. Seen: `dvd_check.c` (split from `dvd_broadway.c`). **HIGH**

- **A small function must exist on its own** (the original calls it with `bl`, ours got inlined): `#pragma dont_inline on` ... `#pragma dont_inline reset` around its definition. Seen: `src/mo_enemy/sora_enemy/em_extend_param_accesser.cpp`, `gf_file_io_handle.cpp`, Melee `lbfile.c`. **HIGH** (prefer `reset`)
- **Builder constructors in fighter RELs are separate functions:** `include/ft/builder/ft_builder_noinline.h` explicitly instantiates each module builder under `dont_inline`. Include it once per character. **MED-HIGH**
- **Only the instruction order differs** (loads/stores interleaved differently, registers right): `#pragma scheduling 603` around the function, then `reset`. Seen: `mt_matrix.cpp`, `gf_model_animation.cpp`. **MED**
- **A 4-float copy whose loads and stores alternate** (`lfs/stfs` pairs in source order): `#pragma scheduling off` around the function. It made other Havok functions worse, so apply it per function. Seen: `getFirstVertex` in `hkBoxShape`, `hkCapsuleShape`, `hkTriangleShape`, `hkCylinderShape`. **MED**
- **`#pragma dont_inline on` around a constructor also stops its base constructor from inlining into it.** To keep only the constructor itself out of line, put `__attribute__((never_inline))` on its declaration. Seen: `hkBvTreeAgent`, `hkMoppAgent`. **MED**
- **A static/data item nothing references gets stripped:** `#pragma force_active on` (dtk generates this at the top of REL units). **HIGH**
- **A zero-initialized global must live in `.data`:** `#pragma section ".data" ".data"` plus `__declspec(section ".data") s32 X = 0;` (upstream `st_onlinetrainning.cpp`). **MED-HIGH**

- **Two identical immediate arguments replace the native load-and-copy pair:** after verifying the callee and values, function-scoped `opt_propagation off` can retain the copy. In Yoshi's kinetic dispatcher, an accesser local declared before the shared flag also preserved the native argument-load order; disabling propagation alone swapped two instructions. Bracket with `push`/`pop` and mark the policy `MATCH-ONLY`. Seen: `src/mo_fighter/ft_yoshi/ft_yoshi_kinetic_transactor.cpp`. **MED**

## 2. Inlining
- **A vector policy macro has no effect:** define `MT_VEC2F_CTOR_NOINLINE`, `MT_VEC2F_ASSIGN_NOINLINE` or `MT_VEC3F_CTOR_NOINLINE` before the first include that reaches `mt_vector.h`, including builder headers. Defining it afterward cannot change an already parsed declaration. Seen: `ft_yoshi_kinetic_transactor.cpp`. **HIGH**
- A callee that our build inlines but the original calls with `bl`: verify the callee identity and inlining policy; use the documented `dont_inline` / `never_inline` controls when that boundary is supported. Do not add dead statements merely to exceed the inline threshold. The old dead-statement trick was observed in Melee, not evidence of Brawl source structure. **MED**
- **A split blob that is really several source files (nwc24, so):** calls that crossed file boundaries in the original (`bl`) get inlined when everything shares one TU. `#pragma auto_inline off` for the whole file, then mark the helpers the original did inline within one file as `inline` by hand. A global that was both emitted and inlined into a sibling needs an `inline` helper plus a thin wrapper (`NWC24iRequestShutdown`, `NWC24iRegister`). `#pragma dont_inline on` around a definition also turns off inlining *inside* that function, and `__attribute__((never_inline))` is rejected by GC/3.0a3. Seen: `src/RVL_SDK/nwc24/nwc24.c`, `src/RVL_SDK/so/so.c`. **MED-HIGH**
- Statics from several original files in one TU share one `.bss` anchor, so functions that touch two of them show small `addi` offset diffs (about 99.9% in objdiff) even though the code is right. Only a real per-file split fixes that. **MED**
- A pointer test that compiles to `li r0,0` + `cmplw` instead of `cmpwi r3,0` after an inlined helper: write `if (!OSGetCurrentThread())` rather than `== NULL`. Seen: `nwc24.c` calling-status checks. **MED**
- Template or inline member functions that must exist as separate weak functions: explicit instantiation (`template Elm& Arr::at(s32);`) in a unit split by address range. This is how the `so_array_*` units work. **HIGH**
- Force a direct (non-virtual) call: qualified name (`p->Base::method()`). **HIGH** (C++ rule)
- Last resorts: inline `asm {}` with `register` locals, or `nofralloc` asm functions (`mt_matrix.cpp`). Mark with `// MATCH-ONLY:` and a reason.

## 3. Floats
- **A zero and tuning float occupy the opposite FPRs:** name the zero, store it, then declare/load the tuning local before its store. Predeclaring the tuning local before the zero retained the wrong pair in both Super Dragon helpers. Seen: `ft_yoshi_kinetic_transactor.cpp`. **MED**
- **A named float array duplicates literals elsewhere in the same unit:** try ordinary float literals first; MWCC can pool them behind one section base automatically. Dedede's ascent unit then reproduced its native four-float pool and improved both large callbacks without a synthetic table. Verify values and the whole pool, especially when differing function sizes make a constants checker unavailable. Do not add dead references or unused locals to force layout. Seen: `ft_dedede_status_uniq_process_special_super_jump_jump.cpp`. **HIGH**
- **Constant pool order is wrong, or a constant is present that nothing uses:** MWCC lays constants out in order of first use. Fixes: a dummy function mentioning the constants in order (`(void) 0.5f; (void) 500.0f;`), or an unused local (`float unusedMin = -90.0f;`, as in `ft_status_uniq_process_glide.cpp`), or `extern const float g_...[]` defined in a data split. Same trick for strings and `.bss` order. Seen in Melee (hundreds of sites), Petari and ours. **HIGH**
- **A fighter global initializer has uniform offsets that are too large:** check whether local-static singletons were encountered before the globals. Puff needed the parameter-accesser and class-info definitions before its fighter constructor, as in Marth. The initializer then matched without padding. Seen: `src/mo_fighter/ft_purin/ft_purin.cpp`. **MED**
- **Float literals need the `f` suffix.** Without it you get a double constant (`lfd` plus `frsp`). **HIGH**
- **int to float:** the `lis 0x4330 / xoris 0x8000 / lfd` sequence is just `(float)i`. The source type picks the constant (`u32` has no `xoris`). **HIGH**
- **`fabs` without a trailing `frsp`:** check both MWCC intrinsics: `__fabs` returns double, while `__fabsf` preserves float arithmetic without a conversion. Assigning `__fabs` to a float can add `frsp`; using its double result directly can introduce `fmul` instead of `fmuls`. Puff Rollout attack power matches with `float horizontal = __fabsf(speed.m_x)` and a named float sum before multiplying. Seen: `ft_purin_status_uniq_process_special_n.cpp`. **HIGH**
- **`fsub/fsel/fsub/fsel` pairs and no branches:** a clamp via `nw4r::math::FSelect(v - lo, v, lo)`. If you see `fcmpu/ble`, it is a plain branchy clamp. **MED**
- **`fcmpu` operands swapped:** try `x != 0.0f` vs `x`, or `0.0f != x`. **HIGH**
- **A struct copy is `lwz/stw`, a field copy is `lfs/stfs`:** to get word copies, use a union of floats and `u32` pairs (`include/so/templates/so_controller_impl.h`). Tag it `// MATCH-ONLY:`. **HIGH**
- **`sqrt`/`rsqrt`:** Brawl code calls `rsqrtf(x)` (declared in `mt_common.h`), with a guard against tiny values; see `ft_status_uniq_process_glide.cpp`. **MED-HIGH**
- **Do not add `volatile` merely to pin temporaries or copy order:** it changes observable accesses. Preserve it for hardware, shared-state or other evidenced volatile semantics; for a scalar copy, check typed member assignments and the unit's scheduling policy first. Seen: `src/havok/hkMotion.cpp`. **HIGH** (C++ semantics)
- **`fmuls` + `fadds` where the original has `fmadds`:** the unit needs `fp_contract on` (`extra_cflags=["-fp_contract on"]` or `#pragma fp_contract on`). Havok math is built this way. Seen: `src/havok/hkVector4.cpp` (0 to 4 of 5 exact), `hkMatrix3`. **HIGH**
- **`isnan` compares `r3` with 1:** this MSL's `__fpclassifyf` returns `FP_NAN` = 1. nw4r's billboard code guards `VEC3Normalize` this way. Seen: `src/nw4r/g3d/g3d_calcview.cpp`. **MED**

## 4. Classes and the C++ runtime
- **A constructor reloads zero where the original copies another zero argument:** verify the formal parameter type and whether its mangled name was reconstructed. Marth's slope call became exact with a boolean axis selector: the callee stores a byte, both update paths test zero/nonzero, and all 48 audited callers pass 0 or 1. The reference map supplied no parameter types; the earlier integer signature was scaffolding. Narrow unsigned types also reproduce the copy, so keep the boolean interpretation labeled as a hypothesis. Seen: `include/so/slope/so_slope_module_impl.h`, `include/ft/builder/ft_module_builders.h`. **MED**
- **Deleting destructors:** write a normal virtual destructor and `delete p`. Do not write the `if (this)` or the `-1` flag by hand. **MED**
- **Havok deleting destructors inline `deallocateChunk` with a class id:** the class has `HK_DECLARE_REF_ALLOCATOR(<memclass>)` (include `havok/hkMemory.h`); without it the dtor calls a generic delete. Seen: `hkCylinderShape`, `hkBoxShape`, `hkCapsuleShape` (memclass 0x25). **HIGH**
- **Havok `cleanupLoadedObject(void* p)`:** write `((hkBaseObject*)p)->~hkBaseObject();`. `delete` adds a null check the original lacks. The matching `finishLoadedObject` constructors must use the `hkFinishLoadedObjectFlag` constructors of their `hkArray` members, otherwise the arrays get zeroed. Seen: `hkBallSocketChainData`, `hkGenericConstraintData`, `hkConvexVerticesShape`. **HIGH**
- **A template destructor calls its whole base instead of destroying the base's member:** check the vptr owner and declaration order before changing inline limits. In Marth's kinetic hierarchy, representing the root as empty and declaring the pool's virtual destructor before its subpool member preserved the native member offset and matched the hierarchy teardown. Declaring that destructor after the member made MWCC use offset zero. Keep this model scoped until other units are reviewed: applying it globally lost exact functions in other fighters. Seen: `include/ft/builder/ft_builder_kinetic.h`. **MED**
- **Vtables and RTTI:** a vtable is emitted in the unit that defines the class's first non-inline virtual (the key function). To force a vtable and its this-adjusting thunks into a unit, construct and destroy an instance under `dont_inline`: `new (p) V(); delete p;`. Hundreds of `so_*_thunks_*` and `so_vtable_ct_*` units rely on this. **HIGH**
- **`-RTTI off` per unit** when the original has no `__RTTI__`. **HIGH**
- **`__dynamic_cast(..., isRef=1)` with no null check:** write `T* p = &dynamic_cast<T&>(*expr);` (reference cast), not `dynamic_cast<T*>(expr)`. About 60 `em_*_param_accesser.cpp` files and `ft_status_uniq_process_damage_fly.cpp`. **HIGH**
- **Global objects with constructors** produce `__sinit_<file>_cpp` plus `__register_global_object` and a 12-byte `.bss` node. **HIGH**
- **Function-local statics with destructors** put their guard and destructor-chain object in different `.bss` regions, so such a function cannot be matched as one unit. **HIGH** (commit 84262f0)
- **Weak copies (templates, inline functions):** the linker keeps one copy, so the original file boundary for template code is unknowable. Splits are by contiguous address range, which is why file names like `_part2` exist. They are scaffolding. Use `tools/weak_dups.py` to name original weak RTTI/vtable copies, and keep a unit `NonMatching` if the hash check fails. **HIGH**
- **Mangled names depend on exact types** (`int` vs `s32`, enum vs int). Spell the original type. **HIGH**
- **Dead stack temp after a call that returns a one-word struct:** `ipPadButton` (a struct with a constructor) returned by value makes fighter code spill the result to the stack even when only `.m_mask` is read. The original code behaves as if the getter returned the plain mask; `soControllerModule::getButton/getRelease` return `int` in the shadow headers (`ft_robot_status_uniq_process_special_arm_spin.cpp`). **HIGH**
- **`#define SO_STATUS_UNIQ_PROCESS_OUT_OF_LINE` only in units that do not own the shared base virtuals:** the first status unit of a REL has to emit the weak `soStatusUniqProcess` virtuals and dtor (leave the macro out there, and give the class no explicit destructor so the vtable uses the base dtor); the others define it. **HIGH**
- **Two copies of a body in consecutive functions** (a virtual hook and a direct entry point, `init`/`initTransact` in `ft_robot_transactor.cpp`): write both bodies out; calling one from the other either gets inlined or not and the stack layout of the Vec3f temporaries differs. **MED**
- **A function the original calls out of line** while MWCC inlines it everywhere: `__attribute__((never_inline))` on the member declaration works, `#pragma dont_inline` placed after the callers does not (`ftRobotTransactor::getLampEffectKind`). **HIGH**
- **Status teardown omits the owned queue destructor:** declare the proved `soArrayVector<s32, 8>` destructor specialization before the builder instantiations when its body belongs to sora_melee. An explicit instantiation under `dont_inline` also worked before the fighter constructor; placing it afterward changed the first instantiation of `getNullArray` and broke Puff’s physics builder and constructor. Check already-exact functions after changing instantiation order. Seen: `src/mo_fighter/ft_purin/ft_purin.cpp`. **MED**

- **A float move appears in the wrong place among constructor arguments:** verify the float's position in the prototype, not just its register type. Moving a float among pointer arguments preserves the PowerPC argument register assignments but changes MWCC's save/move order and mangling. Restore the builder and callee prototypes together, update forwarded calls and symbols, and check already-exact callers. Model scale is second in `soModelModuleBuilder` and follows node setup in `soModelModuleImpl`; this matched Marth and Kirby's builders while retaining the variable-model constructor. Seen: `include/ft/builder/ft_module_builders.h`, `include/so/model/so_model_module_impl.h`. **HIGH**

- **A pointer-to-base conversion adds a null check inside a bounded embedded-object traversal:** a pointer cast must preserve null, while a reference cast expresses a known valid object. When the pool bounds and embedded holder prove validity, pass `&static_cast<Base&>(*object)`; keep the pointer cast on paths that can return null. This removed extra branches and matched R.O.B.’s article deactivation loop. Seen: `src/mo_fighter/ft_robot/ft_robot.cpp`, `include/ft/robot/ft_robot_article_pools.h`. **MED**

- **A virtual call loads floats before its integer arguments, while the original does the reverse:** audit the callee and every caller, then test formal argument order with an external shadow-header probe and a member-function-pointer signature check. Separate GPR/FPR assignment can hide a wrong prototype even when register values are correct. Correcting `soMotionModule::addPartialAnimChr` and `soEffectModule::reqCommon` removed old argument temporaries and matched glide startup, R.O.B. startup/Gyro exit, and Yoshi Egg Roll startup. Slot identity and exact source parameter types still require independent evidence. Seen: `include/so/{motion,effect}/*`, corresponding status units. **MED**

- **`new T[n]` of a plain struct emits `__construct_new_array` and a cookie, while the original calls `__nwa` with the exact size and `delete[]` has no `subi 0x10`:** MWCC treats a struct with a `Vec3f` member (or any user operator) as non-trivial. Allocate the bytes (`reinterpret_cast<T*>(new (heap) u8[sizeof(T) * n])`) and `delete[]` the same `u8*`. Seen: `src/mo_stage/st_dxyorster/gr_dxyorster_blockpos.cpp`. **HIGH**
- **Loads of the constructor arguments (task id, task category, registration descriptor) happen before the first member is constructed:** the original passes them to a builder/config class by value (`soCollisionHitModuleBuildConfig` as one member), so they live in callee-saved registers across the part-array construction. Spelling the arrays and the module as separate members evaluates the loads late. Seen: `include/yk/yk_normal.h`. **HIGH**
- **`Vec3f` assignment copies floats (`lfs`/`stfs`), the implicit copy constructor copies words (`lwz`/`stw`):** a by-value `Vec3f` argument and a `Vec3f a = b;` both use the words; use `a = b` on a default-constructed local to get the float copy. A by-value class parameter also keeps MWCC from folding `0.5f * width` of an inlined helper (a reference parameter folds it). Seen: `src/mo_stage/st_dxyorster/gr_dxyorster.cpp`. **MED**
- **A bitfield cleared with `lbz`/`rlwinm`/`stb` where `&= 0x7F` gives `clrlwi`:** read the byte through a view struct with a one-bit `unsigned char` member and assign 0. Seen: `dxyorsterHitByte` in `gr_dxyorster_blockpos.cpp`. **MED**
- **A derived virtual call is one slot too late:** compare the exact base and derived formal types in the translation unit. MWCC treats `int` and `long` as different overloads even when both occupy one register. Puff's `Weapon::notifyEventAnimCmd` used `int` while its `StageObject` base used `s32` (`long`), adding a virtual slot and shifting `deactivateArticle`. An opt-in matching declaration repaired the call without changing other translation units. Verify the native vtable and all affected call sites before changing shared declarations. Seen: `include/wn/weapon.h`, `src/mo_fighter/ft_purin/ft_purin.cpp`. **HIGH**

## 5. Integers and bools
- **An all-energy mask emits `lis/subi` for 65535 instead of `li -1`:** audit the callee before changing temporaries. Native kinetic speed sums use signed halfword loads and compare against the -1 sentinel; that path sums every enabled energy in reverse order. Correcting `soKineticEnergy::AttributeMask` to `s16` matched Yoshi Egg Roll exit/power callers. Seen: `so/kinetic/so_kinetic_energy.h`, `ft_yoshi_status_uniq_process_special_s_{end,utility}.cpp`. **HIGH**
- The source type decides extension: `u8` gives `clrlwi r,r,24`, `s8` gives `extsb`, `s16` gives `extsh`, `bool` gives `clrlwi 24`. Many "mysterious" extra instructions are a wrong type (often `s8` that should be `int`, or `u8` that should be `s32`). **HIGH**
- **Bitfield reads as `lwz` plus `rlwinm`:** read through a raw `*(u32*)((u8*)p + off)` and shift/mask, not through a declared signed bitfield (`so_damage_module_impl.cpp`). **MED**
- **Loop unrolling happens only for an `int` counter.** `s32` does not unroll. **HIGH** (Melee wiki)
- **Two chained compares** are usually a `switch` with a case range; `if (a < b) x = b; else x = a;` is a ternary/min/max. **HIGH**
- Explicit `== false` / `!= true` comparisons on bool-returning calls match the original codegen in several places (`so_status_module_impl.cpp`). **MED**

## 6. Control flow and registers
Things that moved registers, roughly in the order worth trying:
1. **Reorder local declarations** (declaration order sets virtual register order). Fixed `hkArrayUtil::_reduce`. **HIGH**
   A receiver pointer declared before an owner-ID snapshot can also keep that snapshot loaded before a singleton lookup. R.O.B.'s item cleanup matches with a predeclared `itManager*`, then the task-ID read, then `getInstance()` and `removeItem1(taskId)`; the chained receiver expression deferred the read. Seen: `src/mo_fighter/ft_robot/ft_robot.cpp`. **MED**
2. **Reference temporaries**, the decomp-permuter's output style: `__typeof__(expr)& tmp0 = expr;`. Fixed several Havok functions. **HIGH**
3. **Remove or collapse a temporary** into its single use. **HIGH**
4. **Declare real temporaries before assigning them** in the observed evaluation order (`float y, x;` before computing sin and cos); do not add values that are never used. **MED**
5. **Add a zero or constant temporary** (`float zero = 0.0f;`) to keep a load order. **MED**
6. **Named local reference** to break a common subexpression. **MED**
7. Historical Melee experiments used dead reads, empty conditionals, self-assignment and comma expressions to perturb allocation. Do not transplant these as source reconstruction: recover the real lifetimes and expression order instead. Keep temporary diagnostic experiments outside published source. **MED**
- **Equal-size vector temporaries cycle through the wrong stack slots:** give the kinetic reset vector a named local declared before the earlier deformation vector, then initialize its fields immediately before `resetEnergy`. Declaring it only at the reset call was insufficient. This matched Puff Rollout hit recovery without padding or a new helper. Seen: `ft_purin_status_uniq_process_special_n.cpp`. **HIGH**
- **Charge entry has the right calls but cycles three `Vec2f` slots:** name both the ground reset speed and its target-speed copy, and give each zero rotation a named `Vec3f`. This matched Puff’s normal and full-charge entry functions; hoisting only the aerial speed did not. Preserve the reset vector’s construction before its use. Seen: `ft_purin_status_uniq_process_special_n.cpp`. **MED**
- **Stack frame size is wrong:** first check compiler flags, argument types, inlined callees and real local lifetimes. A temporary padding array can help expose the underlying diff during an external diagnostic experiment; remove it before publishing. A matching frame alone does not justify invented locals. MWCC GC/1.x stack-allocation folklore is unverified for Brawl's GC/3.0a5.2. **HIGH** (review rule; compiler mechanism unverified)
- **Argument evaluation / load order:** an extra reference or temporary of the first-loaded value sometimes moves it (`so_kinetic_energy_normal.cpp`). Some cases never yielded (`fn_106_D4E4`); stop after a few tries and leave a note.
- **Tail calls:** `return f(x)` at -O4 is `b f`; a virtual tail call ends in `bctr` with no `blr`.
- **One- or two-case dispatch on a status kind is a `switch`:** `cmpwi; beq body; b end` (one case) or `cmpwi 0x117; beq; bge end; cmpwi 0x113; beq` (two) is `switch (statusKind) { case ...: ... break; }`, not an if/else chain (`ft_robot_status_uniq_process_special_arm_spin.cpp`). Likewise `cmpwi r3,N; beq .L; b .L` for a single `==` test. **HIGH**
- **`fmuls` operand order flips:** when MWCC emits `fmuls f31, f31, f1` and the original has `f1, f31`, name both operands as locals in the order they are computed (`float a = c(1); float b = c(2); r = b * a;`) instead of nesting the calls (`ft_robot_status_uniq_process_special_arm_spin.cpp`). **MED**
